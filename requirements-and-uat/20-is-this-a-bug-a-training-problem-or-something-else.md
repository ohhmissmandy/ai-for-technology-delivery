# Is This a Bug, a Training Problem, or Something Else?

Use this when testing or early use is producing a pile of feedback and everything is starting to get labeled as a defect.

## Prompt

Review each issue or piece of feedback below and help determine what it most likely represents.

Classify each item using the best fit below, or use another category if none of these fits:

* software defect
* configuration issue
* requirement gap
* misunderstood requirement
* data issue
* integration issue
* usability problem
* training or knowledge gap
* process problem
* expected behavior
* enhancement request
* needs more investigation

For each item, explain the likely classification and why. Then show the business impact, what evidence would confirm the cause, and who should own the next step.

Do not classify something as a training issue simply because the user did not know what to do.

Do not classify something as a defect simply because the user expected different behavior.

If there is not enough evidence to determine the cause, say what needs to be investigated instead of guessing.

Finish with a summary of:

**Likely launch blockers**

**Items that need investigation**

**Items that can be handled outside the defect process**

## What to provide

Paste the UAT findings, user feedback, screenshots described in text, expected behavior, actual behavior, requirements, or other available evidence.
