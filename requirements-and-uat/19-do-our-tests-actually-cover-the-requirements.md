# Do Our Tests Actually Cover the Requirements?

Use this when you need to know whether the test plan actually proves the documented requirements.

## Prompt

Compare the requirements and test scenarios below.

Build a traceability view showing which tests cover which requirements.

For each requirement, identify:

* whether it has test coverage
* which test or tests cover it
* whether the coverage appears complete or partial
* whether the expected result actually proves the requirement
* whether more than one scenario is needed because the requirement includes different roles, conditions, or outcomes

Then identify:

**Requirements with no test coverage**

**Requirements with weak or incomplete coverage**

**Tests that do not clearly trace back to a requirement or business outcome**

**Requirements that are too vague to test reliably**

Do not assume a test covers a requirement simply because they use similar words. Look at what the test actually proves.

Finish with the highest-priority gaps to resolve before testing is considered complete.

## What to provide

Paste the requirements and current test scenarios, including requirement IDs and test IDs if they exist.
